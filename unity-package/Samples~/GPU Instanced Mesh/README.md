# GPU Instanced Mesh

Repository checkouts do not track generated `.threeunity` payloads. Run `npm run samples:generate` before adding this package from disk; packed releases already include the asset.

This sample is generated by `npm run example:instances`. It contains one 2500-instance `InstancedMesh` with deterministic positions, rotations, non-uniform scales, a preserved shear matrix, two material groups, per-instance colors, and a looping transform animation on the whole instance set.

Import the sample from Unity Package Manager, drag `instanced-mesh-gpu.threeunity` into a Scene, and enter Play Mode. The imported hierarchy keeps one GameObject for the source `InstancedMesh`; `ThreeUnityInstancedRenderer` renders its matrices in three batches of at most 1023 instances, once per submesh/material slot. No additional sample behavior script is required.

The renderer uses source-order batch culling. Unity does not frustum-cull or depth-sort individual instances inside a batch, so transparent or very sparse instance sets may need a future spatially chunked representation. Export with `instancedMeshMode: "expanded"` instead when each instance needs its own Collider, MonoBehaviour, metadata, picking, or editable GameObject.
